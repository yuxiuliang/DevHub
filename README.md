# DevHub

本机、单用户的多 agent 协作台。

不是一个把终端平铺在一起的工具，而是**用一套你自己定义的流程，把几个异构 CLI 组织成一个小团队**：
一个需求一个会话，Planner 拆任务，成员各干各的（各自独立 worktree），Reviewer 初审，你终审，合并回主分支。

> 术语：界面上叫「会话」，代码和 API 里仍沿用 `room`。一个会话 = 一个需求 + 一组成员 + 一块任务看板。

## 下载

- [GitHub Releases（最新）](https://github.com/yuxiuliang/DevHub/releases/latest)
- Windows 单文件（Rust，实验）：`devhub.exe`，不需要 Node.js；校验和见 `SHA256SUMS.txt`。

## 快速开始

```bash
node server/index.js
```

打开 http://127.0.0.1:7373 。也可以用 `start.cmd`。

要求：Node.js 22.13 或更新的长期支持版（用内置 `node:sqlite`，不需要 `npm install`），以及 Git。

## Rust 单文件版（实验）

`rust/` 是用 Rust 重写的 hub，复用同一套 REST/SSE 契约和 `web/` 前端，目标是产出不需要 Node.js 的 `devhub.exe`：

```powershell
cd rust
cargo build --release
.\target\release\devhub.exe --port 7374 --data D:\path\to\devhub-data
```

`--port` 指定端口；不指定时先试 7373，被占用会自动尝试 7374–7399。细节、配置和已知限制见 [rust/README.md](rust/README.md)。Node 版保留作为参考实现和回退方案。一个数据目录同时只允许一个 DevHub 实例使用。

## 支持的 worker

自动从 PATH 检测，检测不到会在左侧栏标灰：

| key | CLI | 非交互入口 |
| --- | --- | --- |
| `claude` | Claude Code | `claude -p ... --output-format stream-json` |
| `codex` | Codex CLI | `codex exec --json` |
| `opencode` | OpenCode | `opencode run --format json` |
| `agy` | Antigravity | `agy -p ... --output-format stream-json` |
| `dsh` | DeepSeek Harness | `dsh --profile headless --json` |

DevHub 只负责「什么时候、以什么身份、在哪个目录、拿什么上下文」去调用这些 CLI。
它不实现 runtime，不改这些 CLI 的配置，也不假设某个 CLI 只能做某类事——**角色是你写的，路由是你定的**。

### 需要额外凭据的 CLI

有些 CLI 需要环境变量（例如 dsh 的 headless profile 需要 `WORKBUDDY_API_KEY`）。DevHub 不保存、不展示密钥，只在启动子进程时合并以下来源：

1. 你自己启动 DevHub 的那个终端里已有的环境变量；
2. `.data/env.json`（可选，已加入 `.gitignore`）：

```json
{
  "WORKBUDDY_API_KEY": "…",
  "HTTPS_PROXY": "http://127.0.0.1:7890",
  "DEVHUB_DSH_PATH": "C:\\path\\to\\dsh.cmd",
  "DEVHUB_AGY_PATH": "C:\\path\\to\\agy.exe"
}
```

如果某个 CLI 不在 `PATH` 上（例如 dsh / agy），用 `DEVHUB_DSH_PATH` / `DEVHUB_AGY_PATH` 指定绝对路径；仓库里不内置任何人的本机路径。

`.data/env.json` 只用于解析 CLI 路径和给 agent 子进程补环境变量，不会写进数据库、日志或前端。

## 一次协作的流程

```
会话(需求) → 成员(角色) → 计划(Planner) → 任务 → worktree → 执行 → 门禁 → Diff → 合并
```

1. **新建项目**：选择最近使用的项目或浏览一个项目文件夹，只写一句想做的事。DevHub 会自动命名并生成计划。
2. **检查计划**：计划自动包含任务、负责人和验收条件；需要时可改（包括任务属于哪个流程阶段），再点「确认并开始执行」。
3. **查看成果**：任务完成后打开改动。按任务所属阶段的门禁，可能需要你点「通过」、等评审者检查，或者有产出就直接通过。
4. **合并到项目**：确认后将刚才检查的那份改动合并到基准分支。

## 关键设计

- **上下文隔离**：一个会话一个上下文；会话之间不共享对话、不共享 task、不共享 worktree。多个会话可以同时运行，互不串台。
- **共享什么**：会话需求、已生效的决策、上游任务摘要。Planner 和每个执行者都会拿到这些。
- **执行路径收敛**：Planner 的任务说明里即使写了原始仓库路径，下发给执行者时也会替换成该任务的 worktree 路径，并明确禁止读写工作目录之外的路径。
- **评审只读**：Reviewer 可以读 diff、跑测试，但不能改已跟踪文件或提交。评审前后会比对已跟踪文件的状态和 HEAD；测试产生的未跟踪临时文件不算改动，改动或提交则直接失败关闭，结论不予采用。
- **prompt 走文件**：写到 `.data/prompts/<runId>.md`，命令行只传一句固定指令，绕开 Windows 引号地狱。
- **并发**：全局 3、每会话 2、每成员默认 1；合并全局串行，不会有两个会话同时改基准分支。串行模式下每会话一次只跑一个。
- **可取消**：任务运行可以取消，计划和评审也能从会话顶部点「停止」；总览中的「停止所有运行」可跨会话中止正在执行的任务、计划和评审，并暂停受影响的会话，排队任务与各自工作区会保留，之后可手动继续。取消后，迟到的执行结果不会覆盖任务状态。
- **合并失败后可重试**：如果代码已合并进项目，但任务状态没有保存成功，再次合并可补记任务状态并放行依赖，不创建重复提交，也保留基准分支上的后续提交。合并收尾中的任务、依赖、会话状态和事件一起提交，保存失败时整批回滚，实时更新只发送已保存的状态。未提交文件、冲突或真正的提交失败仍会明确报错。
- **总览直接处理待办**：未确认的计划、执行失败和待检查成果集中显示在「需要你处理」。有待办时，打开 DevHub 会先显示总览；点击事项直接进入对应计划或任务。
- **日志只看最近内容**：任务「日志」默认最多读取最近 128KB、2000 行，显示本次运行状态、退出码和错误；较早日志保留在本机。向上滚动会暂停跟随，点「回到最新」继续。重启后仍可读到中断运行的日志。
- **执行依据可追溯**：任务详情的「依据」标签显示每次执行当时保存的输入原文（`.data/prompts/<runId>.md`）和当时的流程快照（`runs.flow_json`），不会用当前设置重建历史；可以切到更早的运行，输入缺失、被截断、读取失败，或旧运行没有快照，都会明确说明。
- **运行用量如实展示**：任务完成的时间线显示 CLI 返回的 USD 费用，以及 token 总数或输入/输出分项；只有分项时不推算总数，缺少可识别用量时显示运行时长，极小的正费用也不会显示为零。
- **重启后可继续**：DevHub 将中断的任务标为可重试，保留工作区和待办任务。会话会暂停，等你继续执行。
- **设置一起保存**：改名、需求、成员和分工用一次「保存设置」提交；校验失败或写入失败时全部回滚，页面保留输入，能直接重试。名下已有任务的成员可停用，历史归属会保留。
- **未保存内容能找回**：设置和流程的草稿按会话分别保留，关闭编辑窗口、切换会话或在同一浏览器标签刷新后仍可继续；实时任务更新不会覆盖输入。草稿保存在当前标签页，关闭标签页后不保证恢复。
- **旧页面不会覆盖新设置**：其他窗口已保存新版本时，保留当前草稿并提示冲突；选择重新加载已保存内容后再调整。重新读取失败也会保留原输入。会话有任务、计划或评审正在处理时，等待完成或停止后再保存。
- **手动补充任务**：在「更多操作 → 手动添加任务」只写一句要完成的事，标题、类型和负责人会自动补全。服务端核对本会话成员和依赖，保存失败保留输入且不留下半条任务；已完成会话补充新任务后转为暂停，等待明确继续执行。
- **执行提示有明确下一步**：待单独启动的任务可直接打开详情；缺少负责人会指向设置，已取消任务会提示单独处理。只有满足前置条件的就绪任务才显示自动等待，查看详情本身不会执行。
- **会话可维护**：顶部「设置」能改名、改需求、换计划者/评审者、增删成员、改角色/CLI/并发/模型，也能停用成员。停用成员不会被调度。已归档会话只读，恢复后才能继续。
- **归档不删数据**：归档只是把会话置为只读，任务、日志和 worktree 都保留；左侧「显示归档」可以随时找回来。
- **门禁驱动完成**：任务按计划里指定的流程阶段取门禁。`auto` 有产出就直接通过，`agent` 等评审者检查 diff，`human` 等你看完改动点「通过」。只有明确选了阶段的任务才绑定门禁；没选阶段的任务保持原来的「评审通过」。
- **打回有上限**：每个阶段可以设置「最多打回几次」（默认 2）。达到上限仍不通过，任务会升级到总览「需要你处理」，由你决定按意见重跑、人工通过还是取消；升级后的人工打回会再给一次修改机会。
- **流程可编辑**：会话的「流程」标签是一个可拖拽画布（阶段节点 + 门禁 + 产物 + 回边上限）。
  点节点后在右侧用下拉框选「谁来做」、用复选框勾「通过后流向」；负责人可以留空，生成计划时 Planner 会按成员角色分配。
  产物只是可选标签，默认收在「高级设置」里，不选也不影响执行。有任务在跑时只读。
- **流程保存前会校验**：只能有一个起点、每个阶段都要连得上、通过边不能绕成环、打回必须设上限（1-9 次，默认 2）、负责人必须是当前会话成员。不合法时直接指出是哪条规则、哪个阶段，流程不会写入；删掉中间阶段时上下游会自动接上。
- **流程可复用**：新建会话时可以选「复制：某个会话」，把调好的流程整套带过去；也可以从起点模板里挑一个（通用协作 / 代码开发 / 文档撰写 / 调研分析 / 空白）。模板只是初始值，不绑定任务类型，创建后随便改。
- **数据全部本地**：SQLite 在 `.data/devhub.db`，日志在 `.data/logs`，worktree 在 `.data/worktrees`。
- **界面是实时的，不需要手动刷新**：
  - 服务端用 SSE 推送会话事件和 agent 输出，前端按事件增量更新；
  - 运行中的任务卡片直接显示「谁（成员 + CLI）· 跑了多久 · 当前在干什么」，例如 `阿蓝 · DeepSeek Harness  1:24  read src/cart.js`；
  - 成员条显示该成员正在跑的任务和最新动作；
  - 生成计划、自动评审这类不属于任务的运行，用会话顶部的活动条显示；
  - SSE 断线会自动重连，重连后补一次全量同步；右上角「实时 / 重连中」就是连接状态；
  - 5 秒轮询只在 SSE 断开时作为兜底，正常情况下不发任何轮询请求。

## 目录

```
server/
  index.js      HTTP 服务 + 静态托管
  api.js        REST API + SSE
  inputs.js     执行输入的只读读取（历史运行）
  store.js      SQLite schema、流程起点模板、事件总线
  engine.js     会话 / 计划 / 任务 / worktree / 评审 / 合并 / 调度
  adapters.js   五个 CLI 的启动参数与事件解析
  prompts.js    Planner / 执行 / 评审的 prompt 契约
  git.js        worktree、commit、diff、squash merge
  fs.js         本机目录浏览（只读）
web/
  index.html    页面骨架
  app.js        看板、抽屉、计划弹窗、流程画布
  style.css     样式
```

## 已知限制（第一版）

- **worktree 隔离靠工作目录约束，不是 OS 沙箱**：DevHub 会收敛 prompt 里的路径并拒绝越界写入，但 CLI 本身仍有本机文件系统权限；不要给不受信任的 agent 开放敏感目录。
- **门禁按阶段生效，但仍需计划显式绑定阶段**：计划里给任务选了阶段，就按该阶段的门禁和打回上限执行；没选阶段的任务仍走「评审通过」。Planner 不一定会自动填阶段，需要时在计划弹窗里改。
- **依赖在上游合并后才放行**：下游任务要等上游 `merged` / `done` 才会从 `backlog` 变成 `ready`。所以链式任务需要你逐个合并。
- 流程画布支持拖节点、改属性、增删阶段、保存；不支持在画布上直接拖线连边（默认顺序连边 + 评审回边）。
- 任务扇出（一个任务拆给多个成员并行）只留了数据结构，未实现。
- 上游任务失败时，下游会停在 `backlog`，需要你手动重试或取消。
- 没有鉴权、没有多用户，只监听 `127.0.0.1`。
- 只支持 git 仓库；不做非 git 目录。

## 第一次体验建议

1. 点「开始一个项目」，选择项目文件夹，写下你想做的事，再点「创建并生成计划」。
2. 检查自动整理的任务和验收条件，有需要就修改，再点「确认并开始执行」。
3. 成果准备好后，点「查看成果」检查改动，也可以选「自动检查」获取意见。
4. 确认改动后点「合并到项目」。多项目的待确认事项统一显示在总览「需要你处理」。

## 开发自检

- `npm run check`：所有服务端和前端文件的语法检查。
- `npm test`：Git、计划、任务调度、设置事务、日志和 API 回归测试，测试仓库使用系统临时目录。任务操作仅接受 POST；测试覆盖其他请求方法不会启动工具或修改任务、运行和事件。
- `node --test test/merge-atomic.test.js`：单独验证合并收尾的 SQL/事件/COMMIT 失败回滚、故障后重试，以及通知只描述已提交数据；使用临时仓库和数据库。
- `node --test test/gate.test.js`：验证门禁三态（auto 直接通过、agent 评审、human 人工确认）与阶段打回上限：auto 跳过评审、agent 第 N 次打回升级、human 通过/打回、无阶段任务保持旧行为，以及 approve 的错误分支；使用内存夹具，不启动 worker。
- `python -B test/browser_gate.py`：验证门禁在页面上的表现——抽屉完成条件、通过/自动检查/合并按钮、打回上限文案、门禁时间线、请求次数和 390px；加 `--backend all --rust-exe rust/target/release/devhub.exe` 可在真实 Node/Rust 后端上走完 auto/human/agent 三种门禁。
- `python test/browser_smoke.py`：可选的浏览器冒烟测试。已有 Python Playwright 和 Microsoft Edge 时可运行，使用模拟数据验证首次使用路径。
- `python test/browser_loading.py`：验证首次加载状态、服务不可用提示与重试，以及确认无会话后才显示新手引导。
- `python test/browser_workers.py`：验证左侧工具检测、无可用工具提示、检测失败与重新检测恢复。
- `python test/browser_stop_all.py`：验证全局停止的进行中状态、跨会话停止请求、队列保留提示及停止后的空闲隐藏。
- `python test/browser_paused_recovery.py`：验证暂停状态、已取消任务单独重跑提示，以及运行中项目不会被误标为暂停。
- `python test/browser_usage.py`：验证任务完成时间线显示可用的 token/费用，并在无 token 用量时回退到运行时长。
- `python test/browser_inbox.py`：验证总览待处理事项、跨会话导航、窄屏和任务提交重试；可加 `--screenshots <目录>` 保存模拟数据截图。
- `python test/browser_logs.py`：验证失败提示、长日志限长、阅读位置、运行隔离和窄屏；同样支持 `--screenshots <目录>`。
- `python test/browser_editing.py`：验证设置/流程草稿、刷新恢复、读取与保存失败、版本冲突、慢请求、成员增删、键盘操作和窄屏；同样支持 `--screenshots <目录>`。
- `python -B test/browser_navigation.py`：验证会话/任务视图的选中状态、Enter/空格切换、实时刷新与延迟加载时的键盘焦点保留；测试只使用模拟数据，不发起业务写入。
- `python -B test/browser_inputs.py`：验证任务详情「依据」标签的运行切换、正文逐字一致、流程快照渲染、缺失/截断/读取失败提示、迟到响应隔离与 390px 布局；使用模拟数据。
- `python -B test/browser_inputs_real.py --backend all --rust-exe rust/target/release/devhub.exe`：真实 Node/Rust 后端验证执行输入与 `.data/prompts/<runId>.md` 逐字一致、每次运行各存一份流程快照（改流程后重跑，旧运行快照不变）、打回重跑后能切回更早运行的输入与快照；使用模拟 CLI。
- `python -B test/browser_flow_validation.py --backend all --rust-exe rust/target/release/devhub.exe`：真实 Node/Rust 后端验证流程保存校验——选打回目标会自动补上限、删中间阶段自动接上下游、非法图（多起点/通过边成环/负责人不在成员列表）被拒且不写入；另有夹具用例验证服务端错误在画布上的展示与重试。
- `python -B test/browser_queue_guidance.py`：验证自动等待、待单独启动、负责人缺失、依赖阻塞、已取消和无待办等提示，以及查看不执行、明确运行才发出一次启动请求；含 390px 布局。
- `python -B test/browser_task_creation.py --rust-exe rust/target/release/devhub.exe`：真实 Node/Rust 后端验证只填一句话即可手动补任务、归档旧表单保留输入并恢复重试、已完成会话追加后暂停，以及 390px 布局；验证新增和查看不启动 worker，仅在明确运行时调用模拟 CLI。也可加 `--backend node` / `--backend rust` 单独验证。
- Windows 上可在 `rust/` 执行 `cargo build` 后，从项目根目录运行 `python test/browser_flow.py`。测试用临时 Git 仓库和模拟工具，让两套后端走完新建、计划、执行、检查和合并。
- `python test/browser_settings.py`：在真实 Node/Rust 后端上验证设置事务回滚、旧版本冲突和流程保存；临时项目自动清理。两项真实后端测试均可用 `--backend node` / `--backend rust` 选后端，或用 `--rust-exe rust/target/release/devhub.exe` 验证单文件成品。
